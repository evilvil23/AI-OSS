## v0.01 备份功能需求文档
### 1. 总体描述

实现文件备份还原模块，支持**热备份**，提供完整备份、增量备份，支持定时任务、备份生命周期管控、冻结保护，保证数据可备份、可还原、可自动清理。

### 2. 功能需求

#### 2.1 备份源与存储配置
1. 以任务的形式组织备份
2. 支持选择多个源文件 / 目录作为备份对象；支持配置排除文件 / 目录规则。
3. 可自定义备份文件存放目录；目录不存在自动创建，无读写权限直接报错。
4. 支持主动选择任务的备份包是否压缩
5. 通过选择备份任务的备份历史实现还原操作（支持只还原部分文件或全部还原，支持选择还原到原位置或还原到指定位置）
6. 支持在任务执行后发送执行结果到邮箱，来确认任务的完成情况
7. 可以对数据库等文件实施热备份，可以读取正在被其它程序独占打开的文件
8. 可以对USB移动存储设备进行实时监控，当移动存储设备插上时自动执行备份或同步（**USB 设备需要预先绑定到备份任务**，不能任意 U 盘插入就执行备份；防止陌生 U 盘插入误触发。）
9. 定时同时支持**简单周期（日 / 周 / 月） + Cron 表达式**，简单周期内部转 Cron 存储。
10. 任务自动触发模式：实时、定时、间隙或手动地启动任务
11. 元数据存储在元数据在 SQLite中

~~~sql

-- 备份任务表
CREATE TABLE backup_task (
    task_id INTEGER PRIMARY KEY AUTOINCREMENT,
    task_name TEXT NOT NULL,
    source_paths TEXT, -- json数组
    exclude_patterns TEXT, -- json数组
    output_dir TEXT,
    enable_compress BOOLEAN,
    compress_level INTEGER,
    trigger_mode TEXT, -- manual/timer/realtime/interval
    cron_expr TEXT,
    usb_device_id TEXT, --绑定的USB设备标识，为空不监控usb
    max_backup_count INTEGER,
    max_backup_size TEXT,
    enable_email_notify BOOLEAN,
    smtp_config TEXT,
    enabled BOOLEAN,
    create_time DATETIME
);

-- 备份历史元数据表
CREATE TABLE backup_history (
    backup_id INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id INTEGER REFERENCES backup_task(task_id),
    backup_type TEXT, -- full / incremental
    start_time DATETIME,
    end_time DATETIME,
    store_path TEXT,
    total_size INTEGER,
    is_frozen BOOLEAN DEFAULT 0,
    status TEXT, -- success / partial / failed
    parent_backup_id INTEGER, --增量依赖父备份id
    hash_sum TEXT,
    remark TEXT
);

CREATE INDEX idx_task_id ON backup_history(task_id);
CREATE INDEX idx_frozen ON backup_history(is_frozen);

~~~

#### 2.2 备份类型

1. **热备份**：程序运行时执行备份，无需停止业务；对正在写入的文件不强制锁文件，给出风险提示。
2. **完整备份**：复制全部源数据，备份包独立，可直接还原。
3. **增量备份**：仅备份变更文件；依赖已有完整备份才可创建；支持完整还原；还原时校验整条备份链完整性，链损坏拒绝还原。

#### 2.3 定时任务

1. 支持手动触发备份，也支持定时任务；支持间隔周期、Cron 表达式。
2. 任务可启用 / 禁用；同一任务未执行完毕时再次触发，直接跳过本次执行。
3. 记录任务执行历史：时间、备份类型、成功 / 失败、错误信息。（提供单独的备份日志文件backup.log）

#### 2.4 备份生命周期管理

1. **备份配额**：配置最大备份数量、备份总最大存储空间。
2. **冻结备份**：可将备份标记为冻结；冻结备份不计入备份数量、不计入存储空间统计；自动清理逻辑不会删除冻结备份；仅允许用户手动删除。
3. **自动清理规则**：备份完成后执行清理；仅处理非冻结备份；按最早优先删除，直到满足数量、大小双阈值；绝不触碰冻结备份。

#### 2.5 还原功能

1. 完整备份、增量备份均支持还原；支持还原至原路径或自定义目标目录。
2. 还原冲突策略可选：询问用户、直接覆盖、跳过、重命名旧文件。
3. 还原前校验备份完整性；支持浏览备份内文件列表；还原后做文件校验。

#### 2.6 校验与异常处理

1. 备份完成生成校验哈希，标记备份完好 / 损坏状态。
2. 备份前预检查：源目录可读校验、备份磁盘剩余空间校验。
3. 同一时间只运行一个备份任务；备份中途失败，丢弃不完整备份产物，记录错误日志。
4. 提供操作日志：备份、还原、清理记录，支持查看、导出日志。

#### 2.7 备份元数据

每份备份保存元信息：备份 ID、备份类型、起止时间、源路径、存储路径、大小、是否冻结、状态、依赖备份 ID（增量）、校验哈希、用户备注。

### 3. 非功能需求

1. 并发约束：禁止同时运行多个备份任务。
2. 容错：源文件被占用 / 正在写入，做标记，不直接中断整个备份。
3. 风险提示：热备份场景提示高频写入文件存在数据不一致风险。

### 4. 禁止行为

1. 自动清理逻辑**严禁删除冻结备份**。
2. 无完整备份时禁止创建增量备份。
3. 不允许直接还原损坏的备份链。
