任务：为视频文件添加Web端在线播放功能（支持进度拖拽）
1. 需求背景
当前NAS文件管理模块支持文件上传/下载，但用户无法在线预览视频。需增加播放能力，并针对不同清晰度提供差异化体验，提升使用体验。

2. 功能范围
2.1 视频播放

支持的在线播放清晰度：最高 2K（2560×1440）。

支持格式：

.mp4：直接播放（HTTP Range 支持）。

.mkv：后端调用 ffmpeg 进行 转封装（Remux，-c copy） 为 MP4 格式再返回给前端（若浏览器不支持该视频编码，则降级为实时转码，需评估NAS性能）。

超过 2K 的视频（如 4K、8K）不支持在线播放，引导用户下载后使用本地播放器播放。

2.2 高清视频识别与用户引导

后端在返回视频文件信息时，通过 ffprobe 或文件元数据接口，携带视频的分辨率信息（如 width / height）。

前端在渲染文件列表时：

若视频分辨率 ≤ 2K：显示“播放”按钮。

若视频分辨率 > 2K：不显示“播放”按钮，改为显示“高清视频，建议下载后播放”的提示，并提供下载按钮。

播放器内部对超过 2K 的视频进行拦截，弹出悬浮提示窗（Toast / Popover）：

文案：“该视频分辨率超过2K，为获得流畅体验，建议下载后本地播放。是否继续在线播放？”

提供选项：“继续播放”（可能存在卡顿风险）和“下载”。

2.3 进度拖拽

通过 HTTP Range 请求实现，后端需返回 206 Partial Content 及 Content-Range 头。

针对 2K 及以下视频，确保拖拽进度条至任意位置，缓冲时间 < 2 秒（内网环境）。

3. 入口与UI
在文件列表中，视频文件类型根据分辨率显示不同操作：

≤ 2K：显示“播放”按钮。

> 2K：显示“高清视频”标签及“下载”按钮（播放按钮隐藏）。

点击“播放”按钮后，右侧弹出 抽屉式播放器（非新页面）。

播放器使用 Video.js 控件，UI风格与现有管理后台统一。

当尝试播放超高清视频时，触发悬浮提示窗（位于播放器右下角或视频区域中央），样式与系统通知风格一致。

4. 权限与安全
权限：继承当前文件目录的权限，用户只能播放其有读取权限目录下的视频。

播放凭证（Ticket）：

前端打开播放器时，向后端请求一个 Playback Ticket（携带文件ID）。

Ticket 有效期 与播放会话绑定：用户关闭播放器时，前端调用 DELETE /api/play/ticket/{id} 释放凭证；后端兜底超时时间为 30分钟无任何 Range 请求则自动失效。

播放链接携带 Ticket 作为 token（示例：/api/video?file=xxx&token=xxx）。

（可选）Token 与生成时的 IP 绑定，增强防盗链能力。

5. 性能要求
支持 5人同时播放，单文件最大 10GB。

在线播放（≤2K）不转码时 CPU 占用 < 15%。

转封装任务限制最多 3个并发，防止 NAS 过载。

单个转封装任务 CPU 占用不超过 50%。

对于超高清视频（>2K），后端不进行转码或转封装，直接返回提示信息或下载链接，节省资源。

6. 错误处理
文件不存在：提示“视频文件已移动或删除”。

不支持的格式：提示“该格式暂不支持在线播放，请下载”。

转封装失败：提示“视频文件无法转封装，请检查文件是否完整或尝试下载后播放”。

网络中断：播放器显示友好提示并允许重试。

分辨率检测异常：若无法获取分辨率，按“不支持在线播放”处理，显示下载按钮。

7. 测试验收标准
在 Chrome / Firefox / Edge 最新版测试通过。

2K 及以下视频：

显示“播放”按钮，点击后正常播放。

拖拽进度条至任意位置，内网环境（100Mbps） 下缓冲时间 < 2 秒。

后端对 Range 请求返回正确的 206 状态码及 Content-Range 头。

超过 2K 的视频：

文件列表不显示“播放”按钮，仅显示“高清视频”标签和“下载”按钮。

如果用户强行通过其他方式触发播放，播放器弹出悬浮提示窗，文案清晰，选项可用。

关闭播放器后，服务端 Token 自动失效（无泄漏）。

播放器在移动端浏览器上响应式适配良好。
