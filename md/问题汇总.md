## v0.11 2026-08-22 修复记录（元数据存储升级 SQLite）
- **元数据改用 SQLite（方案三）**：文件元数据与历史版本此前以单个 TOML 文件全量落盘，每写一条重写整个文件，浏览大目录的 I/O 与序列化代价随记录数平方级增长。现改用 SQLite（modernc.org/sqlite 纯 Go 驱动，免 cgo，已 vendor），按行增量写入，`parent_id / md5 / deleted_at / share_token / file_id` 建索引，WAL 模式 + 单连接避免锁冲突；Repository 公共 API 保持不变，服务层无感知。性能实测：浏览 2000 文件的目录首次（含 2000 次写入）0.52s、再次 0.32s，数据库仅 324KB
- **位置与配置**：默认 `./data/files/metadata.db`；可在 `config.toml [storage] metadata_db` 指定目录或完整 `.db` 路径（环境变量 `SMARTNAS_STORAGE__METADATA_DB` 同样生效）。已集成验证自定义路径生效、恢复默认后原数据（含文件 ID）完整保留。注意：切换到新位置会使用全新空库（元数据可由浏览重建；回收站/分享/版本等状态保留在原库中）
- **旧数据自动迁移**：首次启动时若库为空且存在旧版 `file_metas.toml / file_versions.toml`（或更早的 `.json`），整批事务导入并保留原 ID，原文件改名 `*.migrated` 留作备份；已用真实数据验证迁移后磁盘 ID 与目录结构完全一致
- **数据库文件屏蔽**：`metadata.db` 及其 WAL 伴随文件（`-wal / -shm / -journal`）不出现在文件列表与 WebDAV 挂载中（复制目录时同样跳过），防止误删导致元数据损坏
- **审查发现并修复的问题**：①时间列以 Unix 纳秒整数存储，`scanFile` 直接 Scan 进 `time.Time` 会失败（每行被静默跳过导致列表为空）——改为经 `sql.NullInt64` 显式转换；②`Update` 中误将 `created_at` 的纳秒值替换为 `time.Time`，导致该列存成文本读回失败——已修正；③优雅退出时关闭数据库句柄（WAL 安全落盘），测试同步补齐 Close 避免句柄占用临时目录
- **保留不变**：`users.toml / settings.toml / uploads.toml` 仍为 TOML（小体量配置类文件，遵循 v0.07 的 TOML 化约定）；RAG 向量缓存 `store.json` 不变
- **测试**：新增 SQLite 单元测试（CRUD 往返/索引查询 ByParent·ByParentName·ByMD5·Search/软删除回收站/版本与裁剪/旧 TOML 迁移保 ID/重复启动不重导/重启持久化）；全量 `go test ./...` 通过；集成验证：真实数据迁移、磁盘 ID 保持、上传→回收站→一键还原、搜索、跨重启持久化、WebDAV 根不暴露数据库与内部目录、自定义 metadata_db 路径、2000 文件目录性能

- **go-astiav 替代 FFmpeg 可行性分析（结论：不可行）**：
